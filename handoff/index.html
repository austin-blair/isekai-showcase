What this is

A single-page recruiting site for Project: Isekai Gacha, an unannounced isekai mobile RPG. Its one job: a smart person who knows nothing about games reads it and wants to help build it. It is not a press kit, a store page or a progress tracker.

Shape of the page

Four layers, one continuous gradient from daylight to night down the whole document. Each layer sets its own room tone; the tone drives ink, accent depth and figure fills, never object colour.

  1. Sky (day) — one line: No one is born a hero here. An arrow down.
  2. Roadmap (overcast) — 14.3% complete, shipped / in progress / scheduled / tracked, the field of 318 marks, and what is in progress right now.
  3. Design system (dusk) — all 15 type sizes, and the whole colour foundation: 598 swatches, 524 distinct values. Every one of them copies itself to the clipboard when clicked; nothing on the page says so.
  4. Open roles (night) — four discipline doors and an email.

The rules that are enforced, not remembered

These are asserted by tests. Breaking one fails the suite rather than quietly shipping.

  • Objects never change with the room. The token generator emits only five tone-scoped properties inside a [data-room=...] block; object colours go to :root where no tone can reach them. A component cannot make a card change colour with the room, because no such variable exists.
  • No panels, borders, dividers, outlines, halos or gold headings. One deliberate exception: the blueprint mark in the roadmap field, where the outline is the subject. It is commented as such and a test guards the comment.
  • No industry vocabulary in content/narrative.ts. Also no calendar dates, no not X, but Y, no anyway, no exclamation marks. gacha is allowed only inside the product name.
  • Nothing fades in, nothing scales past 1.04, nothing bounces. Durations come from the design tokens; src/scroll/motion.ts is the only source.
  • Native scroll is never hijacked. No overflow: hidden on body, no virtualised position. The arrow calls scrollTo on a click — that is a request, not an interception.
  • The page works with no JavaScript and no WebGL. The build prerenders to static HTML; the 3D layer is an enhancement that mounts on top.

The dragon

One wyvern from the owned Unity packs, converted to Draco glb, geometry only, shaded flat as a silhouette that warms from near-black to gold as the room darkens. It lands once — at the very bottom of the page, standing on the footer bar. Scroll up at all and it pushes off again.

None of the flight is keyframed. Five files, each testable on its own:

File What it owns
src/webgl/flight.ts the maths: spring, easing, angles, curves, how much of the world the camera can see
src/webgl/route.ts where it waits, and how it stirs while it waits
src/webgl/manoeuvres.ts what it does on the way
src/webgl/clips.ts which clip is playing and how one gives way to the next
src/webgl/Creatures.tsx the component that drives them

It is solved relative to the camera. The camera travels twenty-six units down the scene as the reader scrolls. With a world-space target the spring chased that, so scroll speed leaked into the velocity and the banking a reader saw was mostly a readout of how fast they were scrolling.

And relative to the frame. A station is a fraction of what the camera can actually see at that depth, not a world offset — the field of view is vertical, so the same offset is a comfortable margin on a wide window and off the side of a phone. The reading column is measured from .layer-inner rather than assumed, a narrow window holds the creature further back, and below the reference shape it is drawn smaller outright.

Ten stations, not four. Keyed on scroll progress rather than layer index, so several sit inside one layer. Between them it takes a curved route: a cubic whose first control point reaches along its current velocity and whose second reaches back along the arrival direction, with the spring chasing a point that runs ahead of it. It bows backwards, so a transit between opposite corners crosses the middle of the screen deep, behind the page. While it holds a station it wanders slowly around it.

Manoeuvres are chosen from the route, not fired off a timer — a long crossing loops, a descent dives with the spring stiffened, a climb pulls a wingover, anything else across the screen rolls, a short hop gets nothing. They are an additive rotation summed on top of the physics attitude, every one starting and ending at rest and finishing on a whole number of turns.

Six clips, chosen with hysteresis so nothing chatters on a threshold, and blended with the wing cycles phase-matched so the beat continues through the transition. The wingbeat rate follows the effort.

It does not track the pointer, and there is no fire. Both were built, then removed on request.

Gotchas that cost real time

Written down because each one looked like something else first.

  • Measure the rig before designing behaviour around it. The neck-to-head chain is half a world unit on a creature four and a half tall. Head-only pointer tracking moved four percent of body height and looked broken. Two fixes were attempted before measuring; both made it worse.
  • Rotating a bone swings what is below it, not itself. Weighting a look chain toward the tip moves nothing.
  • Skinned meshes must not be cloned. clone(true) does not rebind the skeleton, and the stale bind matrices make bounding-box measurement wrong.
  • Normalise models by their own bounds. Source scales vary wildly — this dragon spans 17 units, a golem 2.3.
  • Box3.setFromObject returns world space. Applying that centre as a local offset double-counts the parent's position.
  • Sprite sheets with no alpha write full alpha. Additive blending drops the colour but not the coverage, so a black sheet lands as a black rectangle on a transparent canvas. Derive alpha from luminance.
  • Never resize a WebGL canvas on scroll. The iOS address bar fires resize constantly and resizing an on-screen canvas leaks toward the page-kill threshold. The canvas is sized once against 100lvh.
  • The browser restores scroll after the first read. The descent reads again on the next frame and on load, or a mid-page reload leaves the camera at the top.
  • Exporters duplicate frame zero as the last keyframe. Left in, every loop holds one frame twice. That is the hitch.
  • Hide a model until it is measured. Unscaled at the origin for a frame, it flashes as a pale slab.
  • A grounded clip on an airborne perch reads as having landed. The dragon looked landed halfway down the page because one perch rested on a walk-turn.
  • Stand a creature on its feet, not its bounding box. In most poses the lowest point is a wingtip, so a box-aligned landing hangs it from a wing. The footer line is measured from the element rather than tuned as a constant, so the landing holds at any viewport.
  • Tests that match exact source expressions are brittle. Several broke on refactors that preserved behaviour. Prefer asserting behaviour or exported constants. The flight was pulled out into pure functions for exactly this reason — a spring you can call with numbers can be checked; a spring inlined in a frame loop can only be described in a comment and matched by a regex.
  • A camera-relative target makes the camera part of the physics. Scroll speed leaked straight into the velocity, so the banking, the clip choice and the wingbeat were all partly a readout of how fast the reader was scrolling.
  • Easing of the form min(1, delta * rate) is framerate-dependent. It is a linear approximation that lags at 30fps and races at 144. Use exponential decay.
  • A fixed-timestep accumulator can be worse than no accumulator. The remainder means each frame renders part-way through a step, and that sampling phase wanders — measurably more frame-to-frame variation than the plain integration it replaced. Divide each frame evenly instead; there is no remainder to sample wrong.
  • A single speed threshold makes clips chatter. The drift around a station idles near it, and speed > x flapped between hover and travel the whole time. Separate enter and leave thresholds.
  • Blending two wing cycles of different lengths jumps the beat. Wind the incoming action to the same proportional point in its own cycle first.
  • World-space offsets are wrong at some viewport. The field of view is vertical, so how much is visible across the screen depends on the aspect ratio — eleven units out is a comfortable margin on a wide desktop window and off the side of a phone. State placement as a fraction of the frame.
  • The reading column has to be measured, not assumed. It is a little over half a wide window and nearly all of a phone. A clearance stated as a fixed fraction works on one and puts the creature on a headline on the other.
  • An unsized camera reports an aspect of zero over zero. Any value eased frame to frame will keep that NaN for the rest of the session, and whatever it drives disappears. It looks like a placement bug, not a first-frame one.
  • A weak spring plus a lead point that waits never arrives. The landing is deliberately overdamped and the lead pauses when the creature falls behind: together, ten seconds after reaching the bottom it was still in transit. The landing is not routed.

Known limits

  • No real device has run this. Every check was a desktop browser at a phone-sized viewport. Frame rate on mid-range mobile is unmeasured, and context-loss recovery is unit-tested against a synthetic event only. See docs/verification.md.
  • On a phone the dragon still grazes the occasional label. The reading column is 88% of a 430-wide screen, so there is no placement where a visible creature never touches it. It sits in the gutter at about a sixth of the screen width; on a desktop window the column is 44% and it is fully clear.
  • No sleep or curl-up clip exists on the wyvern rig. The ending is a landing into a grounded idle that eases off. FantasyWolf and EarthTitan have lie-down clips if that beat ever wants a different creature.
  • The foundation ships as data, not as CSS. vendor/colour-foundation.json is the v2 export's data/system.json — fifty named colours with nine-step ramps, fifteen interface roles, and the dark, light, high-contrast and rarity sets. Nothing in it is wired to a CSS variable yet; the booklet renders it so the system is visible, and the page still paints from ui-tokens.json.
  • Wyvern@Falling and Wyvern@GlideToLanding are still unused. A glide-in landing may read better than the stationary-to-landing now that the routes curve; it was not tried.
  • frameloop="demand" is no longer literally true while the dragon is mounted, because its frame body invalidates unconditionally. Harmless, but the comment in Atmosphere.tsx overstates it.
  • Unity VFX graphs do not port to the web. Sprite sheets do; shader-and- particle effects would have to be rebuilt.
  • public/draco/ is 752KB for the decoder, fetched only above tier 0. Dropping Draco would remove it at the cost of larger geometry.
  • Hosted on GitHub Pages, no domain. Live at austin-blair.github.io/isekai-showcase/, served from a separate public repo holding only the built output — this source tree is not published. Deploy is manual: build with SITE_BASE=/isekai-showcase/, copy dist/ into that repo, push. There is no CI step and no custom domain.
  • The link is unlisted, not private. noindex, nofollow plus a robots.txt disallow keep it out of search, and that is the whole of the protection — anyone holding the address can read everything, including the working notes. A static host cannot do better; a real gate means moving to something with a server in front of it, such as Cloudflare Access.
  • The spec names four object sets; only two are tokenised, so the booklet shows two. Tokenise the others and they appear with no code change.
  • The booklet is 598 swatches of prerendered HTML — 279KB raw, which sounds alarming and is not: the markup is so repetitive it compresses to 20KB gzipped and 13KB brotli. Measure compressed before trying to trim it.

Where it stands

Clean typecheck and build, 373 tests passing. Tier-0 devices download about 251KB; the 3D layer is a separate chunk above that. The dragon costs 62KB of code and 914KB of geometry and clips, top tier only, split so that only the 490KB flight set holds up its first appearance — less than it cost before glide and takeoff were added.
